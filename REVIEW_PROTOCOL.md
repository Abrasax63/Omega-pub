# Protocole de revue scientifique

## 1. Objet d'une revue

Une revue doit porter sur un énoncé identifiable : définition, lemme, théorème, calcul, simulation, donnée ou interprétation. Éviter les critiques générales sans cible vérifiable.

## 2. Informations minimales à fournir

Pour toute critique, indiquer autant que possible :
- le fichier et la version examinés ;
- l'énoncé exact concerné ;
- les hypothèses utilisées ;
- le raisonnement ou le calcul contesté ;
- une preuve indépendante, un contre-exemple ou une référence ;
- les conséquences éventuelles sur les résultats dépendants.

## 3. Types de contribution

- Question : ambiguïté ou information manquante.
- Erreur possible : étape ou hypothèse à vérifier.
- Contre-exemple : cas qui invalide l'énoncé ou en réduit la portée.
- Reproduction : vérification indépendante d'un calcul ou d'une simulation.
- Référence : résultat antérieur pertinent dans la littérature.
- Correction : proposition de modification motivée.

## 4. Traitement des critiques

Une critique n'est pas automatiquement correcte parce qu'elle est publiée. Elle doit être examinée à son tour.

Pour chaque point :
1. Accuser réception et isoler l'énoncé contesté.
2. Reproduire le raisonnement ou le test indépendamment lorsque c'est possible.
3. Chercher un contre-test discriminant.
4. Décrire les conséquences sur les résultats dépendants.
5. Publier une réponse motivée et conserver l'historique.

Une critique non résolue reste ouverte et reçoit le statut INDÉTERMINÉ ou À RÉEXAMINER, selon le cas.

## 5. Indépendance et conflits d'intérêts

Les auteurs d'un résultat peuvent répondre aux critiques, mais leur réponse ne vaut pas validation indépendante. Toute relation directe avec le travail examiné doit être signalée lorsqu'elle est pertinente.

## 6. Pas de certification par popularité

Le nombre de commentaires, étoiles, forks ou approbations GitHub ne constitue jamais une preuve mathématique ou scientifique. La qualité d'une revue dépend de ses arguments et de leur vérifiabilité.
