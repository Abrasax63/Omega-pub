## Verrou concret et sources déjà inspectées

Le pilote synthétique #169 est exact sur un monde fermé de 15 partitions, mais n'extrait aucune relation réelle de provenance. Ici, on demande au contrôleur de reconstruire **des groupes de même tentative d'exécution GitHub** depuis des **métadonnées publiques** déjà visibles, sans liste de groupes fournie au logiciel.

Sources publiques identifiées en amont et figées :
- `https://api.github.com/repos/Abrasax63/Omega-pub/actions/runs/44162518044` et `.../44162518044/artifacts` : run PR avec 2 artefacts.
- Runs `44159373482` (PR #168), `44151231771` (PR #160), `44149347157` (push PR #159), `44149424240` (pull_request PR #159), et pour chacun `.../artifacts`.
- Les deux derniers runs ont le même `head_sha=49d9cb31901549088b7baf699f0dd40d84fce8e6`, mais `run_id` distinct. Cela ne démontre ni que leurs calculs sont indépendants scientifiquement ni qu'ils diffèrent dans leurs résultats.

Les sources seront capturées en JSON conservant les champs réels d'API de listing : `artifact.id, artifact.name, artifact.workflow_run.id, artifact.workflow_run.head_sha` et `run.id, run.run_attempt, run.head_sha, run.repository.full_name`. Les snapshots exacts sont des **projections** de réponses API authentiquement vérifiées pendant cette conversation, pas le JSON HTTP complet et pas le contenu ZIP des rapports.

## Regroupements et catégories de preuve

- Clé certifiée **au niveau exécution GitHub** : `(repository, run_id, run_attempt)` **seulement si** la fiche d'exécution existe, `run_id` concorde, `head_sha` de l'artefact concorde avec celle du run et `run_attempt` est présent et entier positif.
- Un même `artifact.id` rencontré plusieurs fois est un **miroir/référence du même artefact**, pas une nouvelle preuve. Deux artefacts d'IDs différents issus de la même clé d'exécution sont **deux artefacts**, pas deux runs. Deux `run_id` différents au même `head_sha` restent **deux invocations GitHub**, pas une seule.
- Des `artifact.name` égaux ne suffisent PAS à dédupliquer ; le commit `head_sha` égal ne suffit PAS à fusionner des runs ; des IDs d'artefacts différents ne suffisent PAS à affirmer deux exécutions distinctes.
- Un champ `run_attempt`, `workflow_run.id` ou `head_sha` absent doit déclencher **ABSTENTION** sur la provenance de cet artefact, pas imputation d'une clé par défaut. Des contradictions explicites entre run et artefact doivent déclencher `CONFLICTING_PROVENANCE` (échec fermé).
- En sortie, on distingue **`execution_grouping=VERIFIED_PROVIDER_METADATA`** (groupement sous hypothèse de fiabilité des réponses API) et **`scientific_independence=INDETERMINATE`**. Même plusieurs GitHub runs ne prouvent pas que les travaux sont indépendants méthodologiquement. Les preuves de version du programme, dépendances, données d'entrée, seeds, machines et auteurs restent à examiner séparément.

## Cas et métriques

Le dossier de base contient 7 **vrais artefacts** de 5 vrais runs (2 du run #169, 2 du run #159 PR, 1 de #159 push, 1 de #168 et 1 de #160). Un test adversarial ajoute des **références dupliquées aux mêmes `artifact.id`** dans une copie synthétique du manifeste ; cette duplication n'est PAS présentée comme découverte dans les données réelles.

Critères de réussite fixés avant code : parser les 7 artefacts source, former **5 groupes d'exécutions** dont deux comptent chacun deux artefacts ; détecter la paire de runs de même commit sans les fusionner ; 0 faux regroupement ; 0 affirmation d'indépendance scientifique ; tests de non-régression sur miroir, champ `run_attempt` absent, artefact falsifié, champ `head_sha` absent, ID inconnu et duplications de noms. Toutes les assertions seront vérifiées depuis la source figée, pas depuis un classement fourni au parser.

**Limite forte :** pas de ZIP téléchargé ni de logs internes analysés, pas d'accès à des déploiements protégés, et les snapshots API sont connus au moment du design. Il s'agit d'une **preuve de fonctionnement d'extraction de métadonnées de provenance**, pas d'un test scientifique indépendant ni d'une nouvelle certitude sur la reproductibilité des résultats mathématiques.
