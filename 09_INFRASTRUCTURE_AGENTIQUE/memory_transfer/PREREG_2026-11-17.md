# OMEGA-TRANSFER-01 — préenregistrement (17 novembre 2026)

## Question
Un modèle Qwen **à poids inchangés** choisit-il mieux une correction sur une tâche tenue à l'écart lorsqu'il reçoit une mémoire de réparations **vérifiées sur d'autres tâches**, plutôt qu'un texte témoin de longueur égale ? Ce test évalue un transfert **en contexte**, pas un apprentissage des poids, et ne peut pas démontrer une intelligence générale.

## Périmètre gelé avant code / exécution
- Base : code de la PR #103, branche expérimentale distincte empilée sur #103 ; `main` intacte, aucune fusion.
- Quatre sources monofautes contrôlées C1..C4 de `multifault.benchmark_sources()`, et une source à deux fautes C5 comme contrôle négatif ; générateur AST et oracle indépendant existants **inchangés**.
- Quatre plis leave-one-fault-type-out : pour chaque cible Ci, utiliser les **trois autres** tâches monofautes uniquement comme entraînement ; pour C5, les quatre C1..C4 sont disponibles. Aucune correction, ligne de faute, étiquette ou résultat fort de la **cible** dans la mémoire.
- Déterminer pour les entraînements les corrections d'une seule ligne survivant à `multifault.discriminant_suite()` via `check_public` et `walks_exact`. Conserver les modifications avant/après et empreintes ; extraction de règle **déterministe**, non apprentissage neuronal, source et grammaire humaines. Une réparation réussie est un exemple, pas un certificat général.
- Pour la cible : même code défectueux, même liste d'IDs des candidats passant seulement les **trois tests publics faibles**, même note scientifique issue du RCE, même Qwen2.5-Coder-3B Q4_K_M épinglé, même `llama.cpp` épinglé, contexte `3072`, sortie `64` tokens, température 0.
- Deux bras : CONTROLE reçoit du texte administratif neutre ; MEMOIRE reçoit les corrections vérifiées des autres tâches. Le texte variable est normalisé à la **même longueur en caractères** ; **l'égalité exacte des tokens n'est pas démontrée**. Alterner l'ordre d'appel des bras selon le pli, consigner ordre, hashes, tailles et durées. Exactement un appel par bras et par cible (10 prévus).
- Le même calcul des entraînements est effectué **une seule fois** et imputé aux deux conditions : ce n'est pas un essai à coût opérationnel total égal, ni une deuxième réplication indépendante. Inclure un comparateur déterministe `first_weak`, identique pour les deux.

## Réserve / falsification
- Générer et figer avant les appels des graphes dirigés avec graines tirées une seule fois, excluant les graines de développement 1101/1102/1103. Logger le SHA-256 du manifeste des **entrées seules** avant tout modèle.
- Ne calculer aucune réponse réservée avant de figer les 10 choix et le SHA de ces choix. Les étiquettes et mutations de cible ne sont jamais transmises au modèle. Évaluer ensuite chaque ID choisi avec l'oracle `walks_exact` et la suite discriminante publique (réservée à l'évaluateur, non à la sélection Qwen).
- Enregistrer pour chaque tâche : statuts d'appel et parsing, coût de construction de mémoire (nombre de vérifications), choix, exactitude, abstentions, changements causés par mémoire, erreurs induites, preuves de provenance et duplications de source.
- C5 est un contrôle négatif : un patch d'une ligne ne doit pas être déclaré réparation complète ; une réponse invalide ou absente = abstention, sans substitution silencieuse.
- Si l'intégrité RCE, du code source, du modèle ou de la séparation des bras échoue, statut INDÉTERMINÉ et arrêt ; aucune promotion CORE.

## Interprétation préfixée
- Une réussite de MEMOIRE sur davantage de cibles que CONTROLE est un **signal exploratoire** seulement : 4 tâches monofautes synthétiques, même algorithme, même grammaire, corpus construit par les concepteurs et aucune indépendance externe.
- Un gain nul ou négatif reste un résultat utile et doit être publié. La seule valeur décisive est la différence mesurée contre contrôle et premier choix symbolique, avec l'écart de tokens et le coût de vérification signalés.
- Aucune modification des poids du modèle, aucun entraînement externe, aucune exécution de code arbitraire rédigé par Qwen et aucune API payante.
