# OMEGA-RUNTIME-CALLTRACE-01 — préenregistrement (2026-11-16)

## Question et antécédents
L'expérience #121 a reproduit le test historique BugsInPy `youtube-dl-1` : `test_match_str` échoue sur la production buggy et réussit sur la fixed avec test transplanté (GitHub Actions [43865942146](https://github.com/Abrasax63/Omega-pub/actions/runs/43865942146)). **Le traceback ne contient aucune frame dans `youtube_dl/`**, donc le localisateur de #120 ne peut pas en tirer un signal. La question nouvelle est : **un observateur d'appels de fonctions pendant l'exécution du test peut-il extraire une information supplémentaire vérifiable**, même quand l'exception finale appartient uniquement à l'assertion du test ?

**Cette étude n'est PAS aveugle ni indépendante.** Le cas historique et son oracle ont déjà été étudiés. Résultat attendu : faisabilité technique, comparaison locale des rangs, identification d'une nouvelle limite, **jamais preuve de généralisation scientifique**.

## Protocole gelé
1. Checkout buggy, transplanter **uniquement le test** en provenance du commit fixed; vérifier son SHA. Exécution `python:3.7-slim` Docker `--network none`, `--read-only`, `--cap-drop ALL`, `--pids-limit 64`, mémoire 512m, CPU 1, `timeout 180s`, pas de secrets, aucune API payante.
2. **Importer et construire la suite unittest AVANT d'instrumenter** pour éviter les imports de modules de bibliothèque de fausser le signal. Activer `sys.setprofile` uniquement pendant `unittest.TextTestRunner.run`. Capturer, pour chaque événement `call` dont `co_filename` est dans `/repo/youtube_dl/`, `chemin relatif`, `co_firstlineno` et `co_name`. Aucune donnée d'arguments, sortie utilisateur ou variable privée. Conserver l'ordre des **premières apparitions** et des **dernières apparitions**, compteurs et hash des traces. Désactiver le profileur même si l'exécution échoue.
3. Le programme doit conserver exit code du test, nombre de tests, échecs et exceptions. Si `buggy` ne reproduit plus le FAIL, ou si aucune fonction de la bibliothèque n'est observée : `PROFILE_REPRODUCER_UNCONFIRMED` / `NO_USABLE_CALL_EVENTS`, sans succès de localisation.
4. Mapper les appels à l'inventaire AST **frozen #121**, par chemin et `co_firstlineno`/fonction; si plusieurs correspondances, priorité à l'intervalle AST le plus étroit, comme dans le parseur #120; appels hors inventaire explicitement comptés.
5. B = score A + **1000 + 10×(rang de récence parmi les appels uniques mappés)**. Pour chaque fonction appelée, prendre son **dernier appel**, la fonction appelée le plus récemment reçoit le score le plus élevé. Aucune autre règle ni information fixe. Tie-break : `(-score_B, chemin, ligne, qualname)`. Critère primaire `hit@10`, secondaires `hit@5`, `hit@20`, `best_rank`. A/B **même inventaire et budget de 10 fonctions**, MAIS B consomme la durée du test instrumenté, donc **PAS de comparaison à coût égal**.
6. Engager le manifeste A/B complet et SHA-256 **avant lecture de l'artefact oracle**. Dans le second job, vérifier ce SHA, puis lire `oracle_targets` du fichier oracle figé de #121 ; jamais de recalcul du correctif ni d'édition des poids. Résultats `NO_DIFFERENCE`, `LOCAL_IMPROVEMENT_ONE_CASE`, `LOCAL_REGRESSION_ONE_CASE`, `ORACLE_PARTIAL`, `INDETERMINATE`.
7. Un même appel peut être présent lors d'un test réussi : **un appel observé n'est pas une cause**. Le résultat n'est ni une correction de bug, ni une découverte de mécanisme, ni une plus-value prouvée d'Omega.

## Tests de non-régression
- Fixture qui appelle une fonction renvoyant une valeur fausse puis lève une assertion **dans le test seulement** : le profileur doit consigner l'appel malgré l'absence de frame du paquet dans le traceback.
- Fixture qui n'appelle aucune fonction du paquet : `NO_USABLE_CALL_EVENTS`.
- Test gel de SHA : un manifeste substitué doit échouer.
- Inventaire et score A strictement inchangés; l'état `ORACLE_PARTIAL` interdit un verdict positif.
- Les tests de succès ne se fondent jamais sur un patch de code fixé ni sur des appels Qwen.
