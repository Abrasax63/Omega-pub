# OMEGA-CYCLE-01 — engagement préalable à un cycle intégré

**Date : 2026-11-15.** Branche `experiment/omega-end-to-end-cycle-2026-11-15`, issue de la PR #85 (modèle ouvert, code isolé) au commit `1db9d396bcb76b5e2ed9e1fd9685630387a89ef9`. Aucun changement de `main` et aucune promotion scientifique.

## Question falsifiable

Peut-on exécuter réellement, dans **un même run** et avec une provenance contrôlée, la chaîne :

1. Mission structurée et plan déterministe P1 ;
2. contexte RCE P2 avec identifiants, statuts et empreinte ;
3. génération et test d'un programme candidat **soit par variantes auditées (contrôle d'intégration), soit par inférence réelle Qwen 3B (essai de création)** ;
4. validation par le calcul exact indépendant de `Q^h` et `Delta_h`, et comparateur classique fort ;
5. décision `REJECTED` ou `REVIEW_REQUIRED` sans promotion automatique ;
6. registre P3, événements de provenance chaînés, rapport JSON et SHA-256 des pièces.

La provenance des modules copiés est donnée par les SHA-1 Git blob récupérés de PR #89 (branche source `83d6d62e...`), tandis que `gate.py`, `model_pilot.py`, `reference.py`, `variant_factory.py` et le sandbox viennent de PR #83/#84/#85 via la branche parente.

**Ne pas prendre l'essai à variantes fixes pour une création ouverte** : il n'invente pas d'algorithme ; il sert à vérifier l'intégration. Le mode Qwen doit effectuer de **nouvelles invocations** pour revendiquer une proposition nouvelle ; il peut aussi échouer et se termine alors sans ouvrir le holdout. Le prompt de base est figé dans `model_proposal.py`.

## Engagements de validation

- La mission et le plan P1 précèdent l'exécution de l'atelier ; le contexte P2 est en lecture seule. Les perspectives P3 non exécutées restent `not_executed`, jamais présentées comme agents indépendants.
- Référence mathématique : `reference.walks_exact` (programmation dynamique ensembliste) et `reference.actual_h_relation` (orbites micro) séparées du code candidat.
- Références classiques : **exponentiation binaire `square-scan` et `square-lowbit`** ; comparaison en budget équitable ; `linear-scan` sert seulement de témoin faible.
- En mode modèle : 2 propositions Qwen2.5-Coder-3B, validations AST, essais de développement, conteneur Docker en lecture seule sans réseau, données de réserve fixées et empreinte imprimée **avant** inférence. Aucun accès aux réponses du holdout pour le modèle ; aucune substitution d'une proposition manuelle en cas d'échec.
- Portes d'arrêt : erreurs de syntaxe / sorties incompatibles / dépassement de ressources / Δ_h non conforme / coût augmenté / faux verdict / absence de gain contre **les deux** classiques forts / provenance incohérente.
- Les coûts Docker contiennent des bruits de lancement ; ils ne démontrent pas une accélération générale. La sélection modèle reste limitée à **deux** propositions et au même contexte public.
- On n'acceptera **jamais** un candidat identique octet pour octet à une référence comme amélioration innovante. Une performance positive peut mener seulement à `REVIEW_REQUIRED` jusqu'à reproduction externe et vérification de l'indépendance causale.
- Le test de contrôle (variantes classiques) conserve son étiquette `TEMPLATE_ONLY`; il ne pourra jamais devenir `CORE`, même s'il est correct et plus rapide qu'un témoin naïf.
- Les données de réserve de l'atelier actuel sont générées dans le même job, non séquestrées par un évaluateur externe. C'est une limite connue ; ne pas parler de preuve externe indépendante ni de découverte.
- `main`, les PR existantes, la bibliothèque certifiée et le registre historique restent inchangés.

## Critère de réussite technique (distinct du résultat scientifique)

Un run CI réussi doit disposer d'un fichier `cycle-result.json` contenant identifiants de mission, empreinte du paquet de contexte, exécutions P3 non simulées, traces de tests et comparateurs, provenance vérifiée, décision et limites ; une erreur d'intégration doit rendre le job rouge plutôt que produire silencieusement une promotion.

**Critère de progrès scientifique :** plus de résultats corrects ou coût inférieur **aux deux** références fortes et dans un protocole prospectif indépendant, sans régression ni faux verdict. Sinon **pas de gain démontré**. La CI seule ne vaut pas certification.
