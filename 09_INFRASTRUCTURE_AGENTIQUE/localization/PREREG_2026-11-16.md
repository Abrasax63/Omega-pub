## Purpose and non-duplication
PR #103 located fault regions in synthetic injected errors; PR #105 froze AST repairs before original BugInPy regressions but selected wrong sites. This add-on isolates whether **a real failing test execution trace** reorders suspicious *sites* better than the unchanged static candidate order in #105. This is not a new reparer or proof of general intelligence.

## Equal candidate and inspection budget
Re-use **exactly** the #105 `blind_candidates.freeze_case` generic seven-rule, at-most-60-candidate code, without modifying it. Deduplicate (path, line) to get sites, at most 60. 
- A `static`: preserve existing #105 candidate order.
- B `trace`: same sites, rank executed lines by most recent observed execution (descending), ties by execution count, then original order; unexecuted sites remain after executed sites. No traceback text or corrected source is included as answer hints.
- Both inspect **at most 10 unique sites**. The trace runs once on the buggy test, and its cost is explicitly counted as extra for B. Results must **not** be described as cost-matched in runtime; only the inspected-site budget is equal. Report the distinct line set, trace counts and trace cost separately.

## Procedural freeze then oracle (two CI jobs)
First CI job downloads ONLY buggy commit, installs historical environment, runs genuine buggy pytest test in offline Docker while tracing *original package Python line events* via stdlib `sys.settrace`, and freezes the candidate pool, two rankings and trace transcript SHA-256 in an immutable JSON artifact. It must not inspect the fixed source/diff. If runtime or trace fails, abstain; never invent dynamic evidence.
Second job downloads the **first job's artifact before fetching fixed source**, revalidates SHA commitments, checks the identical original regression on buggy and fixed snapshots (buggy FAIL/fixed PASS required), then derives independently the true modified old-source file/line sites from the historical `git diff -U0`. Exact old-site hit in top-10 is primary; +/-2-line hit is diagnostic only. A modification at an added-only hunk without old source lines cannot establish exact localization. Do not alter rankings after oracle. Include both negative and indeterminate results.
